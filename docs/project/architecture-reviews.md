# Architecture reviews

Holistic reviews required after every two implementation steps (see `engineering-principles.md`).
Each entry: scope, findings, actions taken, deferred items.

## R3 — after S5 (engagement notifications) and S6 (revocable agent tokens) — 2026-10-01

| #   | Finding                                                                                                                                                                               | Action                                                                                                                                                                                  |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| H1  | Web session issuance (scope ceiling, 8 h lifetime, audience) was still hard-coded in the HTTP route while agent tokens moved into the application. Token policy belongs in one place. | `IdentityService.issueSession` via the `AccessTokenSigner` port; the route only shapes the response. The only remaining direct issuer use is the operator dev CLI and JWKS publication. |
| H2  | An untyped SQL parameter (`$2 - interval`) made every MCP request with a grant-backed token fail as an opaque 500; verification errors were not logged.                               | Explicit cast; unexpected verifier failures are logged (without tokens); regression covered by the agent-token MCP test. Lesson recorded: cast parameters used in arithmetic.           |
| H3  | Supplier notifications send one email per responder inside one job; a partial failure retries the whole job (duplicates for earlier recipients).                                      | Accepted for the pilot (small organizations); per-recipient jobs if it becomes noisy.                                                                                                   |
| H4  | Principal resolution per request: user + memberships, plus grant lookup for agent tokens (one indexed read; last-use write at most every 5 minutes).                                  | Accepted; no caching needed at pilot scale.                                                                                                                                             |
| H5  | The MCP server previously resolved principals in the handler factory, after authentication succeeded, so account-level rejections could not produce OAuth challenges.                 | Principal now resolved inside the token verifier (S6); applies to all future token kinds (OAuth in S7).                                                                                 |

**Boundaries:** application owns all token policy (sessions, agent tokens; OAuth next) behind `AccessTokenSigner`; adapters translate only. Architecture test green.

**Security posture change:** agent tokens are long-lived (≤ 90 days) but individually revocable, scope-capped and not self-mintable by agents; sign-out-everywhere still cuts all of them.

## R5 — final review after S9 (usage gaps) and S10 (deployment) — 2026-10-01

| #   | Finding                                                                                                                                                                                                                                                                                                                                                                                                                      | Action                                                                                                                                                                                                                                                                                                                         |
| --- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| K1  | **Revocation semantics diverged across reviews.** R3 recorded "sign-out-everywhere still cuts all agent tokens"; S7 then added OAuth refresh tokens, which are opaque and mint _new_ access tokens after the `credentials_changed_at` cut-off, so password reset and sign out everywhere no longer disconnected MCP hosts. | K2  | **Configuration is declared in four places** (schema, `.env.example`, `infra/deploy/atx.env.example` + compose, `docs/operations/environment.md`). It found one undocumented variable immediately.                                         |
| K3  | **Orchestrators pass unset optionals as `''`**, which failed URL validation (found by the compose rehearsal, not by tests).                                                                                                                                                                                                                                                                                                  | `loadConfig` treats `''` as unset; the production guard still rejects empty secrets (unit-tested).                                                                                                                                                                                                                             |
| K4  | **Images were not runnable as built**: the non-root user could not run `pnpm` (corepack cache in root's home), and the web container started through `pnpm`, which needs network at runtime.                                                                                                                                                                                                                                 | Shared read-only `COREPACK_HOME`; web runs `next start` directly; verified by running the release commands in the image.                                                                                                                                                                                                       |
| K5  | Operator CLIs duplicated the runtime/close/error boilerplate.                                                                                                                                                                                                                                                                                                                                                                | `scripts/lib/operator.ts` (`runOperatorCommand`, `OPERATOR_CONTEXT`): one place for the system principal and message-only error output.                                                                                                                                                                                        |
| K6  | `SupplierService` is 800 lines: organization profile, catalog content (offerings/capabilities/claims), evidence and assets, sharing ownership helpers (`supplier-access.ts`).                                                                                                                                                                                                                                                | Accepted for now: cohesive "supplier workspace" boundary, and a split would only churn callers. **Trigger:** the next feature touching evidence or assets extracts `EvidenceService` (evidence, external video, upload) first.                                                                                                 |

**Review checklist addition:** for every new credential or token type, list each revocation path (password reset, sign out everywhere, operator revocation, membership removal, organization suspension) and test at least the account-wide ones.

**Overall:** the pilot scope from the launch assessment is complete. What remains are operator decisions (hosting account, DNS, SMTP, counsel-approved legal text, DPA) and the documented known issues in `progress.json`.
