# Expert review (2026-10-02): architecture, implementation, usage, UX/UI

Method: every page was rendered as each role (anonymous, OEM buyer, supplier, platform admin), at desktop
(1366 px) and phone (390 px) widths, from a clean demo database. The findings below cite what was
observed. The code behind each finding was then read, and nothing here is assumed. Every finding has a
proposed change and a step. The status column is updated as steps complete; nothing is closed without a
test.

Severity:

- **Critical**: blocks a core pilot journey.
- **High**: wrong or misleading results, or a trust or security weakness.
- **Medium**: noticeable friction or a scalability limit.
- **Low**: polish.

## Decisions (examined, no change in this round)

- **Version-aware matching** (AUTOSAR R22-11 vs R23-11, QNX 7.1 vs 8.0) is not modelled. Release
  compatibility is not ordinal and varies by standard. "At least" semantics would overstate matches, so
  release tokens stay visible as "unknown terms" and become open questions. Revisit with pilot data.
- **The candidate pool is capped at 80 per query.** This is adequate for discovery at pilot scale, and
  pagination works within the pool.
- **The pruned production image (~1.3 GB) and overlapping signing keys** remain known issues (R5) and are
  unrelated to these findings.
