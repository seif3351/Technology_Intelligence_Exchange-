# Glossary

| Term                                   | Meaning                                                                                                                                                                                                                                         |
| -------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Organization                           | Tenant boundary: supplier, buyer, hybrid or platform.                                                                                                                                                                                           |
| Membership / role                      | A user's role in an organization: viewer < editor < admin < owner.                                                                                                                                                                              |
| Offering                               | Something a supplier provides: product, service or technology platform (type-specific details).                                                                                                                                                 |
| Capability                             | Organization-level competency independent of offerings (e.g. HIL validation engineering).                                                                                                                                                       |
| Concept / facet                        | Ontology node (e.g. `qnx`) and its kind (e.g. operating system). Architectures, platforms, OS, SoCs, protocols, standards, safety and security capabilities are concepts in facets.                                                             |
| Technical claim                        | Structured statement: subject + predicate + concept + qualifiers + statement + provenance. Certifications are `CERTIFIED` claims with a certification body; safety capability is expressed with functional-safety concepts and ASIL qualifiers. |
| Predicate                              | Strength of a claim (supports, designed for, experience with, certified, production deployment, …).                                                                                                                                             |
| Provenance                             | Where an assertion comes from (supplier, public source, licensed third party, internal, AI-inferred, unverified).                                                                                                                               |
| Verification                           | Platform review outcome (unreviewed, platform verified, disputed, rejected).                                                                                                                                                                    |
| Trust tier                             | Derived display/scoring tier from provenance + verification + evidence.                                                                                                                                                                         |
| Evidence                               | Supporting material: document, video, case study, public URL, certificate, production reference.                                                                                                                                                |
| Asset                                  | Binary or externally hosted media with processing state.                                                                                                                                                                                        |
| Requirement                            | A buyer's private technical need with constraints and confidential terms.                                                                                                                                                                       |
| Constraint                             | Concept + level + priority (hard / preference), or maturity / production-reference constraint.                                                                                                                                                  |
| Hard constraint / preference / unknown | Must-have / nice-to-have / term not in the ontology.                                                                                                                                                                                            |
| Assessment                             | Per-constraint result for a candidate: met, partial, unknown, unmet.                                                                                                                                                                            |
| Gap                                    | Missing or weak information with a suggested question for the supplier.                                                                                                                                                                         |
| Match                                  | Candidate offering with assessments, score components, confidence and gaps.                                                                                                                                                                     |
| Demand signal                          | Anonymized aggregate of buyer demand (concept ids only).                                                                                                                                                                                        |
| Engagement request                     | Demo, workshop, PoC or RFI request with an allow-listed disclosure snapshot.                                                                                                                                                                    |
| Confirmation token                     | Short-lived signed token binding a user to the exact previewed payload of an action.                                                                                                                                                            |
| TenantScope                            | Unforgeable proof that the caller is authorized for an organization; required by tenant-private repositories.                                                                                                                                   |
| Audit event                            | Append-only record of sensitive reads/writes and denials (no private content).                                                                                                                                                                  |
